autoresearch on UK HPI

An AI agent ran 12 experiments on a one-file ML script and cut next-month house-price RMSE from £10,256 to £2,322 — a 77.4% reduction.

The setup: prepare.py loads UK Land Registry monthly prices (1990–2026) and builds a frozen feature set with a chronological train/val/test split. train.py is the only file the agent edits — model class, hyperparameters, extra features, target transform, all fair game. After each edit the agent runs the script, reads back val_rmse, and decides whether to keep or revert.

What worked: the three winning experiments

Of the 12 experiments, only three improved on the previous best. Together they account for the entire 77.4% reduction.

1. Tuned regularisation (Exp #3): £10,256 → £2,965  −71%

The single biggest win. The Ridge baseline used the sklearn default alpha=1.0; a small sweep found the small-sample optimum near alpha=270. With ~300 training rows and trending validation prices, much stronger shrinkage was needed than the default assumes.

from sklearn.linear_model import RidgeCV

# Sweep on log-space target — the model has to predict values
# that exceed the training range, so heavy shrinkage helps.
model = Pipeline([
    ("scaler", StandardScaler()),
    ("reg",    RidgeCV(alphas=np.logspace(-1, 3, 50))),
])
model.fit(X_train, np.log1p(y_train))
# best alpha settled around 270; later experiments fine-tuned to 280.

2. Cyclical month + short-horizon momentum (Exp #4): £2,965 → £2,571  −13%

Two engineered columns added on top of the base features. The sine encoding gives the model a smooth, wrap-around representation of seasonality; the momentum term — last month's price minus six months ago — encodes the local trend the model would otherwise have to reconstruct from individual lags.

def add_features(X):
    month = X[:, 1]
    # Cyclical month encoding — smooth and wrap-around
    month_sin = np.sin(2 * np.pi * month / 12).reshape(-1, 1)
    month_cos = np.cos(2 * np.pi * month / 12).reshape(-1, 1)
    # Short-horizon price momentum (lag1 − lag6)
    momentum_1_6  = (X[:, 2] - X[:, 4]).reshape(-1, 1)
    momentum_1_12 = (X[:, 2] - X[:, 5]).reshape(-1, 1)
    return np.hstack([X, month_sin, month_cos, momentum_1_6, momentum_1_12])

X_train = add_features(X_train)
X_val   = add_features(X_val)

3. Feature selection: drop the noisy ones (Exp #12): £2,571 → £2,322  −10%

Counter-intuitively, the final win came from removing features. Four columns — the 6-month rolling mean, the 12-month rolling std, the cosine month term (redundant given the linear month and month_sin), and the longer 12-month momentum — were dropped after ablation showed each one degraded validation RMSE. Alpha was then re-tuned to 280.

What we tried that failed

Nine of the twelve experiments were reverted. The interesting pattern: every “more-sophisticated” class of model lost to a well-tuned linear baseline.

The pattern is consistent: on ~300 training rows with a trending target, anything that adds parameters (boosting, polynomials, stacking, ensembles) loses to a well-tuned linear model. The agent kept the change only when the validation RMSE moved in the right direction — no narrative carried weight on its own.
